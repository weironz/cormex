# Codex 会话采集、存储和展示

本文描述当前工作区的实现，供排查和后续开发使用；不代表生产环境已经部署了这些改动。通用架构与术语见 [会话档案架构](session-archive-architecture.md)。

## 项目与聊天

界面使用“项目”和“聊天”两个对象：项目组织聊天，聊天可以没有项目。Agent 类型是来源维度，不是第三种业务对象；代码和 API 内部的 `session` 标识继续保留以兼容已有数据。空项目不单独采集或展示，项目列表来自已采集聊天的归属。

从 Codex `archived_sessions/` 采集的聊天在 Cormex 中按正常聊天展示，并标注“来自已归档聊天”。`source_archived` 表示至少有一个已采集聊天文件来自宿主归档目录，是来源信息，不代表宿主当前的归档状态。已有原始目录路径保存在 capture 文件记录中，标签可直接从历史数据计算；本功能不会将文件还原回 Codex，也不会替用户改变 Codex 的归档状态。

标签目前只针对有明确目录证据的 Codex 来源生成；ChatGPT 导入等其他来源没有在当前导入链路中保留可靠归档标记时，不猜测添加标签。

远程机器、云环境沿用标准采集部署：在数据所在环境运行采集端并连接同一 Cormex 服务。本机扫描不会自动跨 SSH 遍历远程聊天；当前不增加特殊的远程采集通道。

## 数据从哪里来

内置 catalog 在 `CODEX_HOME` 指定的目录或 `~/.codex` 下发现 `sessions/` 和 `archived_sessions/` 里的 `rollout-*.jsonl`，从文件名提取原生会话 ID。也支持同名 `.jsonl.zst`，明文文件优先，同名压缩文件视为同一个逻辑来源。另有按设备区分的 Codex memory 快照；memory 文件不等同于聊天会话。

采集程序读取文件，不改写原始 rollout。`cormex init` 可以配置 Codex hooks 和周期同步，并默认运行首次回填；这些配置属于宿主集成，具体行为取决于 init 的参数与选择。后续同步按本机 SQLite 状态、文件变化和预算增量处理；截断或重写会形成新 generation，上传失败或预算耗尽可能需要后续同步继续处理。一次同步完成不等于后台投影已经完成。

`.zst` 文件不一定声明原始内容长度。声明长度时使用该值；没有声明时，通过流式解压计数获得逻辑长度，不将整个解压结果保留在内存中。该回退会增加扫描的解压开销。

桌面端原始标题、项目和置顶信息是另一类元数据。当前实现从选定 Codex home 中最新的 `state_N.sqlite` 的 `threads` 表及 `.codex-global-state.json` 读取，并按会话 ID 合并；有显式项目归属时优先使用，没有显式归属且未标为无项目时，才尝试用工作目录与项目根目录精确匹配。**普通 `sync` 不自动上传这批元数据**：当前需要显式运行 `cormex sync --agent codex --codex-metadata`。并非所有远程项目、缺失索引或未来版本的数据都能匹配成功；未识别应保持未分组，不应当作已确认归属。

## 存储和投影

项目根目录比较会对 Windows 的 `\\?\` 长路径前缀、UNC 路径及斜杠进行词法归一化，然后进行精确匹配；不会将任意子目录自动并入项目。侧栏列出的远程项目、空项目不代表本机存在对应 rollout。dev 数据是上次本机同步的快照，新产生的会话需要再次同步。

1. CLI 使用设备凭据经 `/capture/*` 注册来源。服务端记录会话、文件、generation、分块偏移和校验信息；原始块存放在对象存储的 capture 命名空间，元数据存放在 PostgreSQL。
2. 有 `CORMEX_SECRET_KEY` 时，采集块使用数据密钥加密并由主密钥保护；没有配置时按当前部署策略可能以明文存储。密钥丢失或不匹配会影响已加密块的读取。备份需要同时覆盖数据库、对象存储及密钥管理，具体参见 [运维手册](../operations.md)。
3. 后台 masker 和 projector 分别处理原文字节遮罩与结构化事件。Codex 的 JSONL 由 `codex@1` 解析为用户消息、助手消息、思考、工具调用、工具结果、系统和其他事件；`session_meta`、`turn_context` 及重复的 `event_msg` 作为 meta 处理，避免重复展示。解析进度携带 generation 偏移和解析器 checkpoint，便于断点续处理。
4. 投影事件存入 `transcript_events`，保留 generation、来源偏移和长度。当前投影对正文和部分内容块执行遮罩，不能假定所有结构化字段或敏感信息都被识别。原始块仍是另一层数据，不应把遮罩后的视图理解为原文已被永久修改。检索索引和可选的记忆抽取是后续加工，与会话原文入库不是同一件事。

## 角色、最终答复与过程

Codex 的 `response_item` 中，消息可能带 `payload.role` 和 `payload.phase`，后者可以区分 `commentary` 与 `final_answer`。当前历史投影没有独立保存这些字段。读取 Codex 事件页时，服务端根据投影记录的 generation 和来源偏移回读归档块，只提取允许的角色和阶段字段，再随事件 DTO 返回；未脱敏的原始正文不会通过这一恢复步骤返回给页面。

恢复按邻近来源范围批量读取：单条记录上限 1 MiB、单次窗口上限 8 MiB。原始块不可读、记录过大、JSON 无法解析或字段缺失时，角色 / 阶段保持未知，页面不应仅凭猜测隐藏答复。格式或枚举可能随上游变化，需继续按真实样本和测试验证。该恢复逻辑发生在读取时，并不是已经将所有旧投影永久回填。

默认对话视图隐藏可识别的上下文、工具事件、思考，以及明确标为 `commentary` 的助手消息；明确的 `final_answer` 留在对话中，阶段未知的助手消息保守显示。“查看过程”展示相关过程事件，提问前可识别的准备信息会折叠成一组。部分历史记录中的已知内部文本仍有展示层兼容规则，角色和阶段缺失时不能保证与 Codex 原界面完全一致。

思考事件只有源记录提供可读 summary / content 时才能显示对应文字。若源记录仅包含 `encrypted_content` 而没有明文摘要，Cormex 能看到事件存在，但当前无法从该字段得到可读思考；不能把空白解释成已经成功恢复了思考正文。

## 权限与限制

### 记忆页与提取设置

档案提取默认使用 `qa@4`：完整问答附项目、原始标题、真实角色及有限前文，自动回查有界归档工具记录作证据；抽取后再进行独立的自动语义校验。普通处理和小样本验证共用处理器，无人工审核队列。内部指令与思考不作为用户事实，工具日志只作为证据，不执行日志中的命令。详见[完整问答提取与摘要](memory-qa-extraction.md)。没有复用价值时允许生成零条记忆。

记忆详情在桌面居中、窄屏全屏，默认渲染 Markdown，可切换原文并打开原聊天。列表批量补充项目、角色、标题和保留依据，避免逐卡下载聊天。新记录自动注明“归档工具佐证 / 原对话给定 / 来源报告”；来源报告按其证据层级表述，无需用户再次审批。

界面只保留“记忆”和“会话摘要”。系统自动决定保留、去重、更新或舍弃，不要求用户说“确认”或逐条审核。未采纳建议和一次性分工放摘要；有复用价值的项目报告带来源限定。相同主题的新状态追加事实版本，更强证据可更新来源，较弱报告不覆盖更强记忆。旧评审和事实保留审计，不展示为待审任务。

“聊天档案”保存原始聊天；“记忆”展示从聊天提取的长期事实，两者分别处理。记忆页通过账号级的 `/settings/memory-extraction` 获取开启状态、模型配置以及已检查 / 待处理聊天数、累计生成的记忆数。已检查不等于必然生成记忆，进度也不以聊天列表当前加载的条数计算。

开关、模型名称、服务商和服务地址保存在当前账号的数据库中。首次未保存设置时继承 `CORMEX_PROMOTE_ENABLED`；保存后使用账号设置，重启仍然有效。可选择服务端默认提取模型或自定义模型；自定义模型的 Key 使用现有主密钥加密保存，读取接口只返回配置状态与尾号，更换服务商或地址不会自动转发旧 Key。该设置只控制聊天档案到事实记忆的提取，观察摘要的 distill 流程仍单独控制。

开启后按批处理已有和新增聊天；暂停在下一次模型调用前生效，已经发出的调用可能继续完成。提取失败不越过失败消息，保留前面已成功的处理位置，状态页显示错误，后台延迟重试，用户也可手动立即重试。修改模型会在后续调用生效，不重算已完成聊天。“测试已保存的模型”只向保存的服务发送固定短提示，不发送聊天正文。

页面在记忆标签可见且仍有待处理聊天时定期刷新进度；切到聊天档案或打开设置页时停止轮询。模型配置就绪与连接成功分别判断，已配置模型不代表网络、凭据或模型名已经通过实际调用验证。

模型配置统一放在“设置 → 模型配置”。记忆页只保留状态、统计和设置入口。该页面也显示服务端向量服务的就绪状态：LLM 连接正常并不代表向量服务可用。宿主机运行 dev 服务时，需要将 `CORMEX_EMBED_ENDPOINT` 指向已映射到宿主机的端口，而不是 Compose 内部的 `embeddings` 主机名。

小样本验证是独立的有界任务，不打开全量开关：每次明确选择 1–3 个短聊天，合计最多 8 条可见对话消息、24000 字符，每个聊天最多 200 个来源事件。准备样本时复用对话视图的角色 / 最终答复识别；内部上下文、思考与工具不会送给模型。启动前检查真实向量请求，配置不满足时不发送历史聊天。任务整体最多运行 5 分钟，每轮最多 90 秒，逐轮保存进度，失败或停止后不再追加调用，也不会自动扩大范围或重启后继续付费任务。

仅完整检查过的样本聊天推进正常提取游标，因此后续全量提取可以接着处理新增消息。小样本记录保留选中的聊天、处理消息数、关联记忆数及结果；取消时已发出的请求可能完成。记忆出处页可查看对应输入原文及角色，并打开原始聊天。累计生成数包含历史版本，当前有效记忆数可能更少；默认浏览最近 100 条有效记忆，关键词搜索仍按相关性返回有限结果。

### 项目目录和聊天分页

聊天档案首次通过 `GET /archive/projects` 获取完整的项目目录和各项目的聊天总数，不下载全部聊天摘要。只统计已经有投影事件的聊天，跳过空项目；没有项目的聊天归入“未分类”。项目归属以最新采集的 UI 元数据为准，元数据明确没有项目时，不再回退到旧的文件项目字段。

项目默认收起，展开时通过 `GET /archive/sessions?project=...&limit=30` 获取第一页；未分类使用 `unassigned=true`。之后只有点击“加载更多聊天”才读取下一页，游标以最后活动时间和聊天 ID 排序，避免相同时间戳造成重复或遗漏。再次展开已加载的项目复用页面内缓存；刷新、切换来源或搜索会清空分页缓存。聊天正文仍在选中聊天后独立按页读取。

来源和搜索条件同时用于项目目录和聊天分页。搜索在服务端分页之前匹配原始聊天标题（没有原始标题时回退到首条用户文本）或项目名称 / 标识，不局限于已经展开的聊天，也不是全文正文搜索。目录中的数字是全部匹配聊天数，不是当前已加载数量。该加载方式是应用的默认逻辑，不依赖 dev 手动操作。

聊天列表显示的是“对话消息数”：口径与默认对话视图一致，排除可识别的内部上下文、思考、工具、子任务通知及明确标记的过程说明。未知阶段的助手消息保守计入。原始 `event_count` 保留为详情中的“事件”数，不作为消息数展示，也不通过除以二推算轮次。

后台对已完成的投影按页读取消息候选、恢复 Codex 角色与阶段，缓存统计到 `archive_message_counts`。缓存绑定投影 ID 和统计规则版本，聊天追加后旧统计不再用于展示；原始块暂时不可读时统计保持待处理并稍后重试。历史投影的序号可能有空洞，不将最大序号当成真实消息数；带 `at` / `as_of` 的历史筛选不会复用当前聊天的消息统计。列表只读取缓存，不为统计同步回读全部聊天原文。尚未有有效缓存时显示“消息数统计中”。

事件列表读取使用档案读取权限；原始字节接口单独检查 `raw:read`，并受遮罩和审计逻辑约束。可见消息仍可能包含敏感业务内容，应按实际部署的账号、设备和网络边界保护。浏览器中的远程图片不会在会话展示时自动加载。

当前会话列表的项目 / 标题恢复依赖采集到的元数据；丢失的源文件、没有导入的云端会话、源格式不支持的内容和上游没有提供的明文无法凭投影补回。单次验证的文件数或会话数不能证明其他机器、其他账户或未来新增历史也已完整采集。

## ChatGPT 导出导入的现状

个人 ChatGPT 账户可以按照 [OpenAI 官方数据导出说明](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data) 申请 ZIP 导出。Cormex 当前 CLI 接收的是解压后的 JSON 文件，而不是直接处理 ZIP：

```powershell
cormex import "C:\path\to\conversations.json" --platform chatgpt
cormex import "C:\path\to\conversations.json" --platform chatgpt --yes
```

第一条是预览，第二条才向当前 Cormex 配置的服务上传；命令在预览时也会加载本机服务配置和凭据。先核对当前连接指向哪个服务。对于拆分为多个 JSON 的导出，应先确认各文件是受支持的会话数组格式，再逐个预览；不要假定所有导出版本都能解析。

当前实现将导出拆成每会话一个 JSON 快照并以 `chatgpt_export` 来源上传，后台复用 ChatGPT 导出解析器。解析器优先沿 `current_node` 回溯当前分支；没有该字段时按时间回退，可能混入其他分支。投影只提取可识别、非空且带时间的用户 / 助手文本，图片和附件对象不作为正文恢复。原始会话 JSON 快照与投影文本的覆盖范围不同，不能据此声称附件、分支、项目或原始标题在 UI 中均已完整还原。

这条路径目前是**手动导出快照**，不是从 ChatGPT 账户自动增量同步。当前代码将单个会话快照一次作为一个 capture chunk 发送，而服务端的单 chunk 限制为 4 MiB；大于限制的会话、重复导入和更新后的导出应先在隔离 dev 中验证，不能假定均能成功或幂等。仓库内有合成 fixture 测试，但尚未在本轮用真实 ChatGPT 导出完成端到端验证。
