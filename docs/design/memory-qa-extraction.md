# 完整问答提取与会话摘要

## 当前默认：自动记忆（qa@4）

界面只有“记忆”和“会话摘要”。自动记忆不增加人工审核工作：用户无需再次确认或复述，系统根据完整问答、有限前文和归档证据判断保留、去重、更新或舍弃。人工纠错、删除和查看来源是可选操作。

工具证据来自同轮归档，最多 6 项、合计 8000 字符，命令仅作为来源元信息，绝不重跑。逐字核对引用的消息 ID、角色和原文；有成功执行记录支撑时注明“归档工具佐证”，对话给定的项目要求注明“原对话给定”，只有助手报告时保留来源限定，避免冒充独立验证。工具成功只支持对应观察，不保证其他泛化结论。

抽取结果先保存，再由独立模型步骤自动检查语义：断言是否得到证据支持、是否真正可复用、是否把未采纳建议包装成事实、是否夸大工具验证范围。校验可舍弃候选、收窄表述或补充匹配的原文证据。该步骤不会询问用户。候选与校验结果分别留存，校验失败重试只重跑校验，不重复抽取。已有相同来源与模型的 qa@3 候选可复用，但旧版本事实在当前聊天完成新校验后通过追加纠错退役。

有用输入包括项目事实、稳定约束、表达过的偏好、设计决定和由结果支持的经验。未采纳建议、Worker 分工、临时进度不形成待审卡片，有用背景留在摘要。无复用价值可以零产出；数量本身不是质量指标。

每轮最多三条聚合记忆，正文用 Markdown 交代主题、结论、适用场景及边界。稳定主题 key 用来匹配旧版本；新状态按来源时间追加替代，重复值去重，更强证据可刷新来源，较弱报告不覆盖已知强证据。模型上下文最多八个既有主题；写入前另按候选 key 查询，防止被上下文窗口遗漏的强记忆遭弱报告覆盖。所有原事实与纠错事件仍追加保存。

摘要独立生成，每聊天展示最新版本。小样本仍显式选择、最多 1–3 个聊天、八条可见消息、正文 24000 字符，每聊天最多 200 个来源事件；不会开启全量自动处理。原 qa@2 评审保留内部审计，其分类不再作为用户工作队列。

## qa@2 历史设计与验证

聊天档案负责保留完整证据；记忆负责在后续任务中找回有用、可信的信息。提取数量不是质量指标，分析成功可以产生零条长期记忆。

## 输入与边界

档案自动处理与设置页的小样本验证共用 `qa@2` 处理器。先复用聊天展示的角色和最终答复识别，排除内部系统消息、工具、思考及中间播报，再将连续用户消息和其后的助手答复组成一轮。模型接收实际角色、消息 ID、原文、时间、项目与聊天标题。

邻近背景最多为前两轮且合计不超过 6000 字符，整轮超出预算时不截断后冒充完整问答。单轮正文上限 24000 字符；已有摘要最多 6000 字符，用于增量概括。普通后台处理按来源分页，不预先下载整个档案；活跃尾轮和未答复问题暂缓，成功轮次才推进新版游标。

输入仍是待分析数据，不能覆盖提取系统指令。委派任务中的 `user` 角色不自动等于人类本人的长期偏好。

## 四类输出

| 类别 | 保留什么 | 默认长期检索 |
| --- | --- | --- |
| 已确认长期信息 | 用户明确确认的稳定偏好、项目约束、已采纳决定 | 是 |
| 待确认建议 | AI 建议、未采纳方案、尚未核验的完成报告 | 否 |
| 临时状态 | 当前 Worker 分工、进度、一次性限制和任务状态 | 否 |
| 会话摘要 | 背景、讨论、当前结果和待确认项的 Markdown 回顾 | 否 |

模型每轮最多给出六个候选，其中长期信息最多三个，允许候选为空。每个候选需说明保留理由并引用真实消息的逐字片段。服务端验证消息 ID、角色和引文；只有助手证据、委派输入、提问或缺少明确用户确认的条目，不能进入长期事实。该检查偏保守，可能漏掉隐含确认；它不承诺理解所有自然语言歧义。建议仍保留待确认语气，不因模型置信度较高就自动成为决定。

## 存储、重试与来源

问答输入存入来源 episode，标记 `extraction_unit=qa_turn`、规则版本及当前轮/背景消息 ID。评审结果先保存到 `memory_qa_analyses`；之后只有 confirmed 候选调用现有事实写入器、实体解析与向量流程。向量失败后可复用已保存评审，同一来源、规则和模型的重试不会再次请求评审模型。

候选、理由和证据保存在 `memory_qa_artifacts`；独立会话摘要保存在 `memory_qa_summaries`。这些是账号内的派生读模型，状态和摘要允许更新；原始 episode、事实和纠错事件仍走追加式写入。界面按类别分页读取，摘要和候选都能打开来源聊天。确认事实的详情另提供原始问答和逐条保留理由。

对明确选中并完成新版复核的聊天，旧单消息策略结果追加 corrected 纠错事件，退出当前长期检索，保存到“旧策略记录”供对照。不会物理删除原始事实，不重写历史，也不会顺便重算其他聊天。

## 小样本与全量

小样本必须显式选择 1–3 个聊天，合计最多八条可见消息、24000 字符，每个聊天不超过 200 个来源事件。任务最多五分钟，单轮最多 90 秒。记录本次检查消息数、已确认/建议/临时/摘要数；零条已确认信息也可正常完成。

试提取不会开启全量自动处理，也不会在服务重启后自动继续付费调用。当前验证范围为先前选定的两个 Cortex 聊天；其他聊天保持未处理。

## 可以用来做什么

- 接入 Cormex 的 agent 可通过现有记忆检索或 MCP，在新任务中找回已确认的项目约束、偏好和决定，减少重复说明。
- 人可以按主题阅读摘要，找回当时的问题、讨论和结果，再跳回原始聊天核对。
- 建议和临时状态帮助人工回顾或续接任务，但不会混进默认长期事实检索。
- 旧策略记录和追加的纠错事件用于解释“以前为什么记住，现在为什么不再采用”。

采集与提取不会自动给所有 Codex 聊天注入记忆。调用方需要接入检索，并决定何时查询、选哪些内容进入上下文。现有直接 `POST /episodes` 的外部单记录写入接口保持兼容；上述完整问答策略针对聊天档案的自动处理和小样本入口。

## 本地 dev 验证（2026-11-01）

使用原先两个 Cortex 样本重新评审，真实模型为已配置的 DeepSeek Flash，未扩大范围。两份输入均为 user / assistant 两条消息，无额外邻近轮次，识别为委派任务；数据库逐条核对四条输入正文与原投影一致，候选引文全部能在对应角色消息中逐字找到。

| 输出 | 数量 | 质量判断 |
| --- | ---: | --- |
| 已确认长期信息 | 0 | 无用户对评审建议或完成报告的后续采纳确认 |
| 待确认建议 | 7 | 保留建议、待核验报告及其理由/原文证据 |
| 临时状态 | 2 | Worker 分工、只读/不递归委派等本轮执行边界 |
| 会话摘要 | 2 | 分别概括背景、讨论、当前结果、待确认事项 |
| 旧策略记录 | 36 | 原事实保留，追加纠错后退出当前检索 |

小样本任务完成 2/2 个聊天、4/4 条消息；全量仍关闭，另外 2298 个聊天未处理。旧策略记录实际分页为 30 + 6 条，未丢失或重复。浏览器验证了独立 Markdown 摘要、候选证据与来源聊天跳转。

验证包括四项角色/确认规则测试、数据库中的范围/取消/缓存复用/延后调度/来源抹除回归，后端基础测试 150 项，以及 Flutter 全套 80 项测试与静态分析。有限样本验证不等于所有来源与所有自然语言表达均已覆盖。
