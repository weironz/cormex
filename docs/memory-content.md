# 记忆体内容设计 —— 存什么、怎么存

> **迁入说明（2026-10-29）**：本文档回答「什么东西有资格进记忆」，正文按原样迁入。
> 哪些陈述已经过时、与 2026-10 新调研的一致与冲突之处，见
> [research/2026-10-agent-memory-survey.md](research/2026-10-agent-memory-survey.md) §10。

[memory.md](memory.md) 回答的是**记忆系统怎么工作**（存储模型、双时间轴、检索、同步）。
这份文档回答一个它没回答的问题：**什么东西有资格进记忆，什么东西不该进。**

问题是被两个具体场景逼出来的：

1. agent 帮你改一个文件 —— 文件内容进不进记忆？
2. agent 在你的代码库里干活 —— 整个 repo 进不进记忆？

两个问题背后是同一个：**agent 看到的东西千差万别，凭什么决定哪些值得记。**

> 本文档的结论建立在 2026-08 的一轮全景调研上：六条视角（开源框架源码级 /
> 闭源产品 / 编码 agent / 架构论文 / 经验知识持久化 / 数据治理与风险）
> + 四轮一手来源核证 + 一轮完整性批评，覆盖 58 个系统。
>
> **核证推翻了三条初始断言**，那三处在下文标注为「核证更正」。
> 凡属**厂商自评**或 **2026 年未经同行评审的预印本**，引用处均已标注 ——
> 见 §十一⑦⑧：连我们引用的评测基准本身都有 6.4% 的答案是错的。

## 零、一句话结论

**落盘无判据，提炼才有判据 —— 但「原始层」的边界本身就是一个判据。**

原始层 = **对话全文** + **工具轨迹**（命令 / 路径 / 成败 / 一行结论）+ **文件引用**。
在这个边界**之内**无差别落盘，判据只作用于「从原始层向事实层晋升」这一步。

**工具输出的原始字节不在边界内。** 这是本文档最反直觉的决定，
理由见 §二③（检索污染 / 秘密永久化 / 无失效机制的膨胀），
对应 §十已否决的「读到了顺手存一份」。

分工的先例来自 MemGPT：recall storage 无筛选保存消息史，
重要性判断只发生在向 working context / archival 晋升的那一层。
**但我们在边界上与它有意分歧** —— 它的 recall storage 明确包括 function call 的
输入与输出，我们只留「命令 + 结论」，这也是 §一.2 里各家的共同做法。

> **核证更正**：初始调研称晋升「只在 memory-pressure 中断下发生」。原文实际是
> *"Memory edits and retrieval are entirely self-directed"* —— agent 可在对话中
> 随时晋升，pressure 警告只是驱逐前的显式触发点之一。分工的先例成立，
> 但不要把触发条件写死为 pressure。
> 来源：<https://ar5iv.labs.arxiv.org/html/2310.08560> §2

## 一、业界收敛到了什么

调研覆盖 58 个系统。跨视角一致的收敛点只有六条，其余全是分歧。

### 1. 双层存储是共识：派生层之下必须保留原始层

四个独立证据，动机完全相同：

| 系统 | 做法 |
|---|---|
| Graphiti | `EpisodicNode` 逐字存 `content`，派生边用 `episodes[]` 指回 |
| Hindsight | 即使抽出 0 条事实也永存 document，并提供 reprocess 重抽端点 |
| Mem0 v3 | 悄悄加了 `db.save_messages`，抽不出事实也落原始消息 |
| MemOS | 设 `RawFileMemory` 独立类型 |

Hindsight 的文档把动机写得最直白：

> a borderline document can yield facts on one run and none on the next

**LLM 抽取是有损且非确定的**，原始层是唯一的重放依据。
Cormex 的 `episodes` + `facts` 分层站在正确一侧，而 append-only 让「重抽」天然安全 ——
重抽不需要删旧的。

### 2. 没有一家默认从工具输出**的原始字节**抽事实

但**有多家从工具轨迹抽结论**。这两件事必须分开说，我们之前混为一谈过。

存原始字节的四种姿势，全是「类型化原料」而非「记忆化结论」：

- **Mem0 procedural memory**：逐字全存执行史，prompt 明令
  *"Every output produced by the agent must be recorded verbatim"* ——
  **无失效机制，会无限膨胀，反面教材**
- **Graphiti**：以 `json` 类型 episode 收结构化数据
- **MemOS**：`ToolTrajectoryMemory` / `ToolSchemaMemory` 独立类型
- **Hindsight**：verbatim 模式，原文入库、LLM 只补实体与时间元数据

从轨迹抽**结论**的三家（这是我们之前漏掉的）：

- **Codex**：`should_persist_response_item_for_memories` 白名单**显式包含**
  `LocalShellCall` / `FunctionCall` / `FunctionCallOutput`，
  而 `reasoning` 反被排除
- **Claude Code** auto memory：官方列举保存 build commands 与 debugging insights
- **Devin** Knowledge：官方建议存「常见 bug 及解法、部署/测试流程」

**共同点：各家都只存「命令 + 结论」，不存原始输出字节。**

### 3. 代码库不进记忆，进可重建的派生索引

没有任何一家把代码库内容存进记忆权威：

- Cursor：索引 6 周过期即删，原文 chunk 生成向量后**直接丢弃**，
  服务端只留向量 + 混淆路径 + 行范围
- Aider：repo map 每轮重算
- Cognee：唯一把 repo 当记忆源的，但用 `uuid5(repo, kind, name)` 确定性 ID +
  幂等重抽取（源码注释：*"so re-extraction of a repo updates the same nodes"*）——
  **这本质是缓存语义不是记忆语义**
- Letta：文件是 `FileBlock` 挂载访问通道（open / grep / semantic_search），
  不复制内容进事实库

而反方是两家一手工业复盘 —— 这是查漏补上的，之前只看到了正方：

- **Sourcegraph 2024-02 公开弃用 embeddings**：增量刷新运维复杂、
  代码需送第三方 embedding API、多 repo 规模不可行，改用代码搜索引擎实时检索
- **Cline 2025-07 明确拒绝索引**：chunking 撕裂代码逻辑、
  索引陈旧性随每次 merge 发散、嵌入是代码 IP 的第二份拷贝使安全面翻倍

两家理由高度一致，给出了可推广的判据：

> **能随时从权威源以可接受延迟重建的派生物，不该进记忆体。**
> 陈旧性成本 > 检索加速收益。

对代码，权威源就是 git —— **git 本身就是代码的 append-only 日志**，
我们没有理由再做一份更差的。

### 4. ADD-only 正在战胜 LLM 仲裁的 UPDATE/DELETE

Mem0 从 v1 的四操作仲裁（ADD/UPDATE/DELETE/NONE）**退回**到 v3 单趟 ADD +
`linked_memory_ids`（矛盾是一种链接类型）+ MD5 哈希去重。
MemOS 更新即归档双份旧版。Graphiti 打失效戳不删边。

剩下的分歧只是落法：**就地改字段**（Graphiti / MemOS）vs **追加事件**（Cormex）。
`fact_events` 是这条收敛线的最彻底形态，无需辩护。

### 5. 双时间轴是通用语，不是方言

| 系统 | 表达 |
|---|---|
| Graphiti | 四时间戳 `valid_at`/`invalid_at` vs `created_at`/`expired_at` |
| Hindsight | "when it happened vs when you learned it" |
| MemOS | `timespec` 快照 + `memory_form` state/event 二分 |
| Memobase | 连纯字符串 memo 里都要标 `[mentioned vs occurred]` |
| Omi（开源可穿戴） | `supersedes` + valid_interval 与 commit time 分离 |

**但没有任何一家编码 agent 有这个能力。** Claude Code 用文件 mtime 表新鲜度，
Codex 用 `usage_count`/`max_unused_days` 做频度淘汰 —— 都回答不了
「这条事实在何时为真」。这是 Cormex 目前最实的差异化。

### 6. 遗忘在所有生产系统里都退化为排序与标记，无人真删

唯一实现概率删除的 MemoryBank，其 Ebbinghaus 公式带着算子优先级 bug
（`-t/5*S` 使强度越高忘得越快）跑了两年半没人发现 —— **证明这条路径无人行使**。

反复出现的替代信号是「召回即强化」：MemoryBank `strength+=1`、
A-Mem `retrieval_count`、Letta FileBlock `last_accessed_at`、
Generative Agents 的 recency 从 last-retrieved 起算。

## 二、五类输入 × 三种处理

这是本文档的核心表。**每一格都是一个明确的决定，没有「视情况而定」。**

| 输入 | 归档 | 进抽取管线 | 进检索索引 |
|---|:---:|:---:|:---:|
| **① 对话**（user / assistant） | ✅ 已有 | ✅ 已有 | ✅ 已有 |
| **② 工具轨迹**（命令、路径、成败、一行结论） | ✅ 已有（元数据，非原始字节） | ❌ **← 缺口** | 间接 |
| **③ 工具输出原始字节**（文件全文、命令 stdout） | ❌ **已定案不存** | ❌ | ❌ |
| **④ 版控内文件**（代码） | 存引用（**目标**，§九#5） | ❌ | ❌ |
| **⑤ 版控外文件**（Excel / PPT / 散落文档） | ✅（**目标**，§九#10 阻塞） | 经转录 | 只索引转录 |

> **列语义**：标「已有」= 现状；标「目标」= 本文档的决定，尚未实现；
> ③ 的 ❌ 是**已定案的不做**，不是待补的缺口。
>
> ② 的「归档」是元数据不是字节：`episode_tool_calls` 存
> `name / path / ok / ordinal / summary`。其中 `path` 是从工具参数里逐字取出的
> （`live.rs` 的 `tool_path()`），失败时 `summary` 还带工具输出的首行 120 字符 ——
> **落的是「命令 + 路径 + 成败 + 结论」，正是 §一.2 各家的共同做法。**

### ① 对话 —— 不变

现状已经对，`docs/memory.md` §五的判据继续适用。

### ② 工具轨迹 —— 唯一需要新建管线的一格

`episode_tool_calls` 已经在落库（`name` / `path` / `ok` / `ordinal` / `summary`），
但**抽取器完全不看它**。后果：

> 「这个命令跑失败了三次，第四次加了 `--locked` 才过」
> —— 这条经验现在一个字都留不下。

这正是三家编码 agent 都在做而我们没做的事。要补的不是新表，是让抽取器**多一个输入源**。

抽取判据在这一格要**特化**，因为工具轨迹的信噪比和对话完全不同：

```
值得抽的（硬信号，无需 LLM 打分）：
  · 失败后成功的序列          → 差异就是知识
  · 同一命令反复出现          → 这是这个项目的惯例
  · 用户显式确认的高风险操作  → 它批准过什么

明确不抽：
  · 单次成功的读操作          → 没有信息量
  · 命令的原始 stdout          → 见第 ③ 格
  · 任何未经用户可见的结论    → 见 §四的信任级
```

「失败后成功」这条判据的来源是 Manus 的一手复盘：

> 保留错误记录不清洗 —— 失败痕迹是模型改错的依据

以及 Memp 的消融：带纠错的动态更新优于纯追加。

> **核证更正**：初始调研称 deprecation 有 Memp + ExpeL 两篇消融背书。实际
> ExpeL 的归零删除机制存在但**从未被消融验证**（论文只有一句定性辩护）；
> Memp 的量化优势也仅 +0.7 点且数据在图内。
> **结论**：deprecation 事件流应当作「与 append-only 天然同构的低成本设计」
> 来做，而不是宣称有强实证背书。

### ③ 工具输出原始字节 —— 明确不存

这一格是本文档最反直觉的决定，所以理由要写足。

**「已经读到了，顺手存一份」在成本上确实几乎免费** —— `blobs` 是
`hash sha256 PRIMARY KEY` 内容寻址，同一份内容存一百次只占一份。
但存储从来不是这里的成本。三条真实代价：

**(a) 检索污染 —— 我们刚栽过一次。**
上一轮做 `relates_to` 时，第一版把边的 statement 照常建了索引。
`evals/README.md` 的 A/B 对照（原有 111 题回归面）：

```
A 不建桥          R@5 0.912   MRR 0.807
D 桥 · 边进索引    R@5 0.897   MRR 0.792     ← 掉 0.015 / 0.026
```

**而且跨域题也被拖累了** —— D 的五道新题 gold 名次从 B 的 13/11/2/7/7
退到 15/17/4/6/10，R@10 从 0.600 掉到 0.400。README 原话是「新题反而更差」。

那还只是**一句话**。一个 500 行的源文件塞进 BM25 与向量索引，
后果比这严重一个量级。当时的结论原样适用：

> 修法不是调权重，是想清楚**这行是一条边不是一条陈述** ——
> 用途是被遍历不是被检索。

外部证据是 Chroma 的 Context Rot：18 个 SOTA 模型在输入变长时**非均匀退化**，
远在窗口上限之前（200K 窗口在 50K 输入就明显掉点），**干扰项越多越重**。
（注：Chroma 是向量库厂商，结论方向与其商业利益一致。）

推论对我们的融合层有直接约束：**召回率不是越高越好，宁缺勿滥。**

**(b) 秘密会永久留下。**
路径围栏对 `.env` / `id_rsa` / `credentials` **零排除** —— 这个仓库自己就有 `.env`。
问题不是「读到了」（那是当轮临时的），是**存进一个 append-only 的库**，
还会跟着同步复制到每一台设备。

Windows Recall 的实测教训在这里是决定性的：开启「过滤敏感信息」的状态下，
第三方实测**仍然截获到信用卡号与 SSN**。
**写前过滤必然漏**，所以不能把安全性建立在过滤器上。

**(c) 无失效机制的逐字存储会无限膨胀** —— Mem0 procedural memory 是现成的反面教材。

### ④ 版控内文件 —— 存引用，不存内容

判据是 Sourcegraph / Cline 那条：**可从权威源重建的派生物不进记忆体。**

对 git 里的文件，`路径 + commit sha + 行范围` 就能**精确复原**当时看到的那一份 ——
零存储、无损、带上下文（哪个分支、前后是什么），比存副本还准。

这在形态上就是 Manus 的「可恢复引用」：

> file system as ultimate memory —— 不存原始字节，存可恢复引用：
> 留 URL 丢网页内容、留路径丢文件内容，**压缩必须可还原**

**schema 影响**：记忆体需要「引用型记忆」这个**一等类型**
（URI + 恢复方式 + 摘要），而不是在「存全文」和「不存」之间二选一。

顺带解决一个现实问题：围栏对 `target/` `node_modules/` `.venv/` 零排除。
用引用的话这个问题自动消失 —— 构建产物不在 git 里，自然没有 sha 可引。

### ⑤ 版控外文件 —— 归档 + 抽取文本

Excel / PPT / Word / 散落文档**没有任何其他系统在替你保存历史版本**，
所以归档才有意义。

但要注意一个**内容寻址失效**的事实：`.xlsx`/`.docx`/`.pptx` 都是 ZIP 容器，
**改一个单元格 zip 会被整个重写，SHA-256 完全变一个** —— 去重一点用都没有。
同一原因，byte diff 对它们也无意义。

所以它们走的是**图片那条路**，不是文本那条路：

| | 归档 | 索引 |
|---|---|---|
| 图片 | 原始字节 | vision 转录出的文字与实体 |
| **Office** | 原始字节 | **抽出来的文本与结构** |
| 文本/代码 | 引用 | diff 与结论 |

⚠️ **但 `blob_transcripts.kind` 不是开放枚举 —— 加一档要动两处闭合点。**

它是**闭合 CHECK**：`CHECK (kind IN ('asr','vision_caption','ocr','frame_caption'))`
（`migrations/20260807000001_init.sql:91-92`）。
同一个 migration 里真正「开放不枚举」的是 `entities.kind`，两者容易混。

新增 `office_text` 一档要动：

1. **一个新 migration** 重建约束（CLAUDE.md：不改已应用的 migration，加新文件）——
   内联列级 CHECK 由 PG 自动命名为 `blob_transcripts_kind_check`，
   需 `DROP CONSTRAINT` + 重新 `ADD`
2. **`cormex-store` 的 `TranscriptKind` 补一个变体**（`model.rs`）——
   它的 `FromStr` 对未知值返回 `UnknownVariant`、`Decode` 走 `raw.parse()?`，
   **库里先出现 `office_text` 行会让读取整表失败**

> **顺序不能反：先加 Rust 变体，再写数据。**

tsv / embedding / HNSW 索引是 `kind` 无关的，**那部分确实原样复用**。

**当前阻塞**：`read_file` 用 `std::fs::read_to_string`，遇到非 UTF-8 直接失败 ——
agent 现在**连打开都打不开** Office 文件。这是第 ⑤ 格的前置工作。

## 三、按写入还是按读取

**按写入存，不按读取存。**

只读没改的文件，归档它等于把硬盘复制一份到云上，而那个文件还好好在你机器上。
真正值钱的是 **agent 动过的版本**：改之前 + 改之后。

一次「读十个文件改一行」，按读取存归档十份，按写入存只归档一份 ——
差一个量级，丢掉的信息几乎为零。

## 四、判据：从「单判据」到「判据 + 预算 + 信任级」

现有判据是一个问题：

> 下次对话如果不知道这条，会不会做错决定？

调研显示它**方向正确但维度不足**。要补三样。

### 4.1 补一个正交维度：惊讶度

LangMem 的默认判据是十家里最认知科学的：

> Prioritize retention of **surprising** (pattern deviation) and
> **persistent** (frequently reinforced) information

这与我们的判据正交：我们的判据管**决策相关性**，惊讶度管**信息量**。
两者应当并置成双问题：

```
① 下次不知道这条，会不会做错决定？   （决策效用）
② 这条与已知的偏离有多大？           （信息量）
```

第二问有一个几乎免费的符号化实现：**抽取前对候选做一次近邻检索，
「与已知矛盾」或「近邻为空」即高惊讶度**。这正是 Graphiti 与 A-Mem
用来找矛盾候选的同一次查询，不增加成本。

### 4.2 判据要编译成预算，而不是停在抽象标准

抽取派的写入判据**都以预算形式落地**：

| 系统 | 预算 |
|---|---|
| Omi | 每对话硬编码最多 2 条 |
| ChatGPT | Recent Conversation Content 封顶约 40 条 |
| Mem0 v3 | 10+ 条消息应产出 5-15 条，少于 3 条视为漏抽 |

**预算迫使抽取器对候选排序，比「重要就存」可实现得多。**

同时所有派生记忆都有**硬长度上限**：Mem0 每条 15-80 词、Memobase 每槽 5 句、
Letta 每 block 5000 字符、Hindsight 'what' 1-2 句。

> 上限不是风格偏好，是注入成本与整理压力的来源 —— **写不下才会触发整理。**

**待定**：Cormex 每 episode 的抽取条数预算与每条 fact 的长度契约，
需要用评测集标定，不能拍。

### 4.3 补一个新维度：来源信任级 ⚠️

**这是本次调研发现的最大 schema 缺口。**

Cormex 现有设计只有**读侧**栅栏（注入块首的「记忆是背景数据不是指令」框定）。
但已公开的真实攻击**全部发生在写侧**：

| 攻击 | 形态 |
|---|---|
| MINJA（arXiv 2503.03704） | 仅通过正常 query 交互即可向受害 agent 的记忆库注入恶意记录 |
| AgentPoison（NeurIPS 2024） | 投毒记忆/RAG 知识库植入后门触发器 |
| SpAIware | 经 prompt injection 写入 ChatGPT 持久记忆，实现**跨会话持续数据外泄** |

攻击者不需要碰注入通道 —— 只要让待抽取的内容（网页、工具输出、
对方发来的文本）诱导抽取器写入恶意事实即可。
**而 append-only 会让毒化记录永久留存并持续进入召回。**

Codex 已经做了对应防护：外部上下文（MCP / web search）**可配置排除出记忆生成**。

**结论：`facts` 必须带来源通道与信任级。**

```
trust_tier:
  1  用户亲述            最高
  2  模型从对话推断
  3  工具输出（本地执行）
  4  外部内容（网页 / 他人文档 / MCP）  ← 默认不进抽取，需显式开启
```

三处用途：
1. 高风险来源的写入进**隔离区**（需审查才晋升）
2. 召回排序**按信任级加权**
3. 出事后可**按来源批量失效**（追加一批 `fact_events`，append-only 天然支持）

### 4.4 入库信号分硬软两级

来自经验记忆研究的一致做法：

```
硬信号（无需 LLM 打分）：测试通过 / 编译成功 / 用户显式确认
软信号：模型自评 + 置信度 + 可降权
```

最危险的变体是 AWM 在线版的**「模型自评成功即存」** —— 自我强化污染入口。

ASI 的同框对比给出了为什么：**程序技能比文本技能 +11.3%（WebArena），
差距来源正是可验证性** —— 代码能用测试把坏经验挡在库外，文本不能。

**推论**：Cormex 编码域用「代码 + 测试」表示经验，办公域用「workflow + insight」，
**不要用同一种形态硬套两域**。

## 五、失效、遗忘与删除

### 5.1 失效裁决：LLM 提名，确定性代码裁决

最佳分工出自 Graphiti 的 `resolve_edge_contradictions()`：

> **LLM 只负责提名矛盾候选，`invalid_at` 的赋值是比较 `valid_at` 先后的纯函数。**

把时序裁决从 LLM 手里拿走，换来可测试与可回放。
这与 `docs/memory.md` §五「矛盾消解：确定性逻辑，不交给 LLM 判断」完全一致，
可以直接引用为外部佐证。

触发时机也有成熟答案：**不是后台全表扫描**，而是新 fact 写入时对语义近邻
（top-k embedding 候选）做一次矛盾比对 —— O(k) 而非 O(n²)，
且天然发生在已有 LLM 在场的抽取管线里。

### 5.2 遗忘完全交给读侧

存储上全记住，召回上学会不提。具体机制：**追加 access 事件**。

「检索本身是写入」被三个独立来源支持（Generative Agents 的 last-retrieved recency、
MemoryBank 的召回强化、CLS 的重放理论）。
> ⚠️ **初稿说这是「零边际设计成本」—— 不成立，两处偏离没被承认。**
>
> **① 它是运营数据，不是记忆数据。** `architecture.md` 已把这一类记为长期风险
> （「遥测 / 日志 / trace 类表会随时间膨胀并拖垮同步，需建立
> 『记忆数据 vs 运营数据』的分类纪律」），而 `roadmap.md` 对同构的
> `retrieval_traces` 已经写死相反的纪律：**「豁免同步与『永不删除』」**。
> 说它「append-only 天然支持」等于默认它进 `sync_log` 并永久保留 ——
> 那正是已知会拖垮同步的形态，而且频次比 facts 高一到两个数量级。
>
> **② 它要喂的 recency 路目前是关的。** `evals/README.md` 的「已定案的旋钮」里
> 时间近因是**关**（既不做召回路也不做 decay），关的理由是实测不可判，
> 规矩是「改之前先把曲线重跑一遍」。重开一个定案旋钮不是零成本。
>
> **修正后的形态**：access 事件应当**豁免同步、设保留期**（照 `retrieval_traces`
> 的纪律），且它的消费方需要先把 recency 路的曲线重跑一遍才谈得上开。

这个方向仍然值得做 —— 它补的是 Codex 有而我们没有的第五信号：**被引用会续命**。
只是它属于「运营数据」这一类，纪律与 facts 不同。

### 5.3 删除的派生传播 ⚠️ —— 当前 redact 设计的盲区

**GDPR Art.17 的擦除义务及于派生数据。**

而 append-only 体系里，源事实的墓碑**并不自动**使 embedding、摘要、图边、
画像等派生物失效。如果一条被 redact 的事实已经参与了某次整固摘要、
某条图边、某个画像块 —— **这些派生物会继续泄露它。**

结论性影响：

> **每个派生物必须带 provenance（`source_event_ids`）。**
> purge 实现为：按 lineage 找到所有派生物 → 墓碑 → 从剩余源重放投影。

学术侧独立支持同一结论：抽象必须携带指向源记录的 provenance 边
（Generative Agents 的 because-of 引用、RAPTOR 的树父子、HippoRAG2 的 contains 边）。

> 这不是可选优化，而是失效传播的前提 —— 没有它，源事实被 invalidate 后
> 建立其上的摘要成为**无法追责的僵尸记忆**。

**这要求 schema 从第一天就存派生边，事后补是不可能的。**
`episode_memories` 已经开了这个头（存 fact id 不存快照），
但摘要层与将来的画像层还没有。

## 六、整固：从 episode 到抽象

现有设计只有「抽取」一步，缺一整层。调研显示整固管线只有四种族系，
且**全部保留原始层、追加派生层，没有一家用抽象替换原文**：

| 族系 | 代表 | 做法 |
|---|---|---|
| 反思式问答抽象 | Generative Agents | 从近期记忆生成 salient 问题 → 定向检索 → 生成带源引用的洞见 |
| 递归聚类摘要树 | RAPTOR | 无监督聚类 + 逐层 LLM 摘要 |
| 图化抽取 | HippoRAG / Zep | OpenIE + 实体消解，episode 层明确 non-lossy |
| 离线预思考 | sleep-time compute | 空闲期改写上下文，预答未来查询 |

### 6.1 整固必须有多个节拍

来自 Nested Learning 的频率谱思想 + CLS 快慢系统：

```
回合内     工作记忆              → 上下文窗口
会话末     episode 摘要          → 快节拍
每日/每周  画像重 derive         → 慢节拍，产物天然稳定
```

**慢频层产物天然稳定，恰好放进可缓存前缀**；快频层贴最新消息侧。

> ⚠️ **但「与现有注入设计严丝合缝」这句要撤销。**
> `injection.rs` 里确实有 `render_profile_block`，**但它在整个仓库里
> 只有自己的单测调用** —— cormexd 的对话链路两处注入点用的都是
> `render_turn_block`。也就是说「核心画像块」这个可缓存前缀
> **目前根本不存在于运行系统里**。
>
> 所以整固层（P2）的隐藏依赖比初稿写的多一层：不是「产物往已有的画像块里放」，
> 而是要**先把画像块接进 live 的 prompt 组装**、定义它的来源与刷新时机、
> 并处理它变动时前缀缓存失效的节奏。

整固扫描应**偏置采样**（近期 + 高 surprise + 目标相关），
CLS 明确重放是被奖励与新奇调制的 —— **均匀扫描是浪费。**

### 6.2 ⚠️ 整固绝不能实现为「让 LLM 重写整份画像」

ACE（Stanford/SambaNova/Berkeley，arXiv 2510.04618，ICLR 2026）实证了
**context collapse**：让 LLM 整体重写自己积累的 playbook 会**突然坍缩**。

实测数字：

```
第 60 步   18,282 token   准确率 66.7
下一步        122 token   准确率 57      ← 被重写成这样
```

**整体重写是记忆系统的静默毁灭模式。更新必须是条目化的追加或局部 delta。**

这为 append-only 与 `fact_events` 追加式失效提供了**语义层**的独立证据
（不只是存储层的多端无冲突论证）。

直接约束：**核心画像块的维护必须是增量的**，否则缓存前缀和内容质量会一起被毁。

### 6.3 摘要不需要第五条召回路

RAPTOR 的 collapsed-tree 结论：**摊平所有抽象层级进同一向量索引，
优于层级遍历。**

意味着整固产出的摘要作为普通记忆行进现有 BM25 + 向量索引即可，
让层级在排序中自然竞争 —— 不用改检索代码。

## 七、明确不该存什么

负判据和正判据同等重要，而且各家都付过学费。分四级，每级的**处理位置不同**。

> **三条贯穿全节的原则**
>
> **一、阻断的是派生层，不是 L0。**
> ⚠️ 这一点必须写死，否则会与 §零和 `memory.md` §十一 打架：
> **L0 `episodes` 是唯一真相来源，不能有洞** —— 密钥最常出现的地方恰恰就是对话正文，
> 而对话正文必须原样落盘。所以「硬阻断」阻的是**进抽取、算 embedding、进 tsv 索引**
> 这三件事，**不是「不写 episodes」**。
>
> 真要抹掉已落盘的原文，那是 `redact` —— 而 `memory.md` §十一 规定它
> **「必须显式触发，需二次确认，绝不自动执行」**。自动的写前销毁不在这条例外里。
>
> **二、过滤必须在 LLM 抽取之前、embedding 之前。** 这正是 Mem0 的反面教训 ——
> 它的过滤在抽取层，原文已经完整过了一遍网络。
> CLAUDE.md 约束 2 规定「embedding 计算一律在事务外完成」恰好提供了插入点：
> **过滤与 embedding 同处事务外准备阶段，过滤必须排在 embedding 之前。**
>
> **三、「不该存」≠「不该记录曾经存在过」。** 但留痕的形式因级别而异：
> - **来源级排除**（路径命中）：工具层根本不读，什么都没产生，**无需墓碑**，
>   记一行「因规则跳过」的操作日志即可
> - **内容级命中**：episode 照常落盘，**抽取日志记「本轮因 X 规则未抽」**
> - **已落盘后才发现**：走 `redact`，留 `redactions` 墓碑（`target_kind` 只有
>   `'episode' | 'blob'`，所以墓碑只能挂在真实存在的行上）

### A 级 —— 硬阻断：不进抽取、不算 embedding、不进检索索引

> ⚠️ **不是「不写任何表」** —— 见上方原则一。L0 照常落盘，阻断的是派生层。

| 条目 | 理由 | 代价 |
|---|---|---|
| 私钥块（`-----BEGIN * PRIVATE KEY-----`） | 正则零歧义，信噪比最高 | ≈0 |
| 带厂商前缀的 key/token（`AKIA` `ghp_` `xox` `sk_live_`） | SecretBench 命中率 **87.7%** | ≈0，这类串对判据零贡献 |
| 云连接串与账户密钥 | 抄 Recall 的 Azure 9 类清单 | 低。**结构**（用哪个服务）可留，凭据部分必去 |
| `.env` 形式赋值（key 名含 SECRET/TOKEN/PASSWORD/KEY） | 编码 agent 最高频误入路径。本仓库已有先例（`f6ef0d6`） | 低 |
| Authorization / Bearer 头、JWT | JWT payload 常含身份信息 | 低 |
| **PCI SAD**：CVV / 完整磁道 / PIN 块 | **PCI-DSS Req 3.3 法定禁止，加密也不行，无例外**。审计最常见的发现正是 SAD 泄进**日志、调试 trace、崩溃转储、备份** —— 记忆系统架构上是同一类载体 | 零。card-on-file 与周期扣款本就不需要 CVV |

**优先做来源级排除，而不是内容扫描。**
抄 Recall 的 `SetDenyAppListForRecall`：`.env` / `*.pem` / `id_rsa` / `secrets.*` /
`.aws/credentials` / `.npmrc` / `.netrc` 这些路径**直接不进记忆管线** ——
成本远低于内容扫描，且**零误报**。

### B 级 —— 涂黑后可存（保留结构语义）

| 条目 | 理由 | 代价 |
|---|---|---|
| 信用卡 PAN（Luhn + 留后四位） | PCI 要求**任何位置**（含备份与日志）渲染为不可读 | 低 |
| 邮箱、电话、IP、URL | HIPAA 18 类第 4/6/14/15 项，GDPR 下均为个人数据 | 中。**用 `<EMAIL_1>` 而不是 `***`** —— 朴素掩码破坏任务语义，记忆会失去可用性 |
| HIPAA 号码型标识符（SSN、病历号、账号…） | 第 18 条是**兜底条款**：任何其他唯一识别号 | 低 |
| 姓名、地址 | 同上第 1/2 项 | **较高** —— 人名是关系图的骨架。只对**第三方**（非用户本人、非公众人物）应用 |

### C 级 —— 打标不阻断（存但标记，不进核心画像块）

| 条目 | 理由 |
|---|---|
| 数据库 / 服务器 URL | SecretBench 真阳性率仅 **1.6%** —— 硬阻断会大量误杀正常技术讨论 |
| 无正则命中的泛型高熵串 | SecretBench "Other" 类 **99.29% 是误报**（git SHA、UUID、lockfile 校验和、base64 资产） |
| 健康信息 | 对齐 OpenAI 做法（不主动记，用户明确要求才记）。⚠️ 但见下方实测失败率 |

> **熵只能作为已命中正则后的二次确认，绝不能作为独立的一级判据。**
> `detect-secrets` 的默认阈值（base64 4.5 / hex 3.0）源自 TruffleHog 早期工程启发式，
> **没有找到任何测量过其实际误报率的学术研究**，而学术横评正把
> 「无效的熵计算」列为高误报的两大根因之一。

### D 级 —— 🔴 不该抽成 L1 事实（存了会让系统变笨或违法）

**这是本清单最重要的一节。** 前三级管「敏感」，这一级管「有害」。

| 条目 | 理由（带数字） | 代价 |
|---|---|---|
| **🔴 用户的情绪状态** | **EU AI Act Art.5(1)(f) 已于 2025-02-02 生效**：禁止在**工作场所**推断情绪。条文**未提及生物识别**，只说「使用 AI 推断自然人的情绪」—— 纯文本情感分析落在真实的模糊地带；欧委会要求「工作场所」作广义解释并延伸至招聘。罚则 **€35M 或全球营业额 7%，无宽限期**。Cormex 定位含「办公」 | 低。情绪是回合级上下文，本就不满足「下次不知道会做错决定」 |
| **🔴 GDPR Art.9 特殊类别的推断**（种族、政治、宗教、工会、健康、性取向） | ICO 明确：**只要你有意做出与特殊类别相关的推断，就是在处理特殊类别数据 —— 不论推断是否正确**。Art.9(2) 门槛远高于 Art.6。**Replika 案 €5M 正是踩这条**，而 Replika 在形态上是本次调研中与 Cormex 最接近的一案 | 低。这类推断对编码/办公几乎无用，风险收益完全不成比例 |
| **🔴 关于第三方的个人事实** | 用户没有为第三方提供同意的资格 | **中高**。区分：**角色/职责类可存**（「张三负责支付模块」），**私人属性类不存** |
| **🔴 已被后续证据否定的用户断言** | 抽取的有损压缩把「用户认为 X」编码进记忆、把「助手指出 X 是错的」丢掉 —— 这是**记忆诱发谄媚的主要元凶**，放大最高 **25 倍** | **零，而且是净收益**。见 §七尾「最高性价比的三处改动」 |
| 代码片段、日志、命令输出本身 | 已在 extract prompt 中 ✅。补数字：注入模型本来就知道的冗余内容**掉约 20 点** | 零，L0 已完整保留 |
| 助手自己的推理与结论 | 已在 extract prompt 中 ✅。Codex 白名单也显式排除 `reasoning` | 零 |
| 一次性查询、寒暄、未定论讨论 | 已在 extract prompt 中 ✅。补规模证据见 §七尾 | 零 |
| ~~`valid_at` 无法确定的事实~~ | 🔴 **这一条已撤销，见下方框** | —— |

> ### 🔴 撤销：`valid_at` 兜底那一条
>
> 初稿把 Graphiti 的「`valid_at IS NULL` 的边永不失效」类推到我们身上，
> 并提议「事实为现在时 → `valid_at` = reference_time」。**两处都错，
> 而且那个「修复」会造成真实的数据损坏。**
>
> **① 我们没有那个漏洞。** `active_facts` 视图**根本没有时间闸门** ——
> 它只按 `fact_status` 的末态过滤：
> ```sql
> WHERE s.op IS NULL OR s.op = 'revoke';
> ```
> `valid_at` 为 NULL 的事实与其他事实一样能被失效。Graphiti 的失效路径要过
> 两道要求非空的时间闸门，我们的不过 —— 架构不同，风险不迁移。
>
> **② 兜底早已实现，而且实现得比这个提议更对。** `extract.rs` 在矛盾比较时
> 回落到系统时间，但**刻意不写回**，注释逐字写着：
>
> > `facts.valid_at` 允许为 NULL（未知或一直如此），但比较必须有个值，
> > 于是回落到该行的系统时间。**不把这个回落值写回 `valid_at`** ——
> > 那等于用「我何时知道」冒充「何时为真」，双时间轴就白设计了。
>
> 而双时间轴正是 §一.5 认定的「我们目前最实的差异化」。
> `migrations/…init.sql:161` 也写明 `NULL = 未知或一直如此` 是**刻意的语义**。
>
> **教训**：把别家源码里的漏洞类推到自己身上之前，先确认失效路径是否同构。
> 这条差点作为 P1 排进施工单。

### 「存得越多越好」被证伪的实测证据

这些数字是 D 级存在的理由，也是 §四预算判据的依据。

| 场景 | 硬数字 |
|---|---|
| 语料 N→10N | 每 10× 索引掉 **12–25 个 MRR 点**；768d 从 88.99 → 17.34 |
| 1 亿索引下**纯乱码压过正确答案** | 稠密 **8.5%–12.1%**；**BM25 恒为 0.00%** |
| **1 条**近似干扰文档 | Llama2 .5642 → .4586（**−18.7%**）；18 条 → .1795（**−68.2%**） |
| 黄金文档在场反而**不如闭卷** | MPT 8 篇干扰（中间位）.1002 **<** 闭卷 .1205 |
| **1 条过时事实 > 6 条无关噪声** | 过时 **−24%** vs 无关 **−2%**（差一个数量级） |
| 检索退化远陡于生成退化 | FR@10 **−62%** vs 生成质量 **−8%** |
| **hard negative 训练救不了** | ADORE（SOTA 检索器）**比 Contriever 更差** |
| 更强检索器 → 更差生成 | e5（R@40=0.90）退化重于 BM25（0.73） |
| **100 条无关 session 即崩** | HippoRAG 跌破 70% 可靠性；最强模型撑到 300 条 |
| 记忆本身放大谄媚 | 加记忆后准确率 49.12 → **26–36**，谄媚率 27.43 → **44–65** |
| 连贯上下文比无序噪声**更**干扰 | 打乱 haystack 句序，**18 个模型全部变好**（Chroma，**厂商自评**） |

> **唯一的硬阈值**：注入 **100 条无关 session** 后 HippoRAG 类系统跌破 70% 可靠性。
> 该论文的方法值得直接借鉴 —— **保持任务证据完全不变，只往记忆里注入无关 session**。

**一条反向平衡**：过滤过度同样有害。激进的时间过滤是最常见的失败模式
（某方案时序正确率 .921 但**召回仅 .002**）。宁缺勿滥不等于宁可不要。

### 最高性价比的改动 —— 初稿三条错了两条

> ⚠️ **初稿把这三条列为「零成本、有 A/B 对照、今天就该做」。
> 核验发现前两条建立在错误的现状判断上。** 保留原文与更正，
> 因为「怎么错的」比「正确答案」更值得记住。

**1. ~~抽取时严格纳入 assistant turns~~ —— 我们早就做了**

初稿声称「抽取只看 user turn」。**事实错误。** 生产路径上唯一的抽取入口是：

```rust
// crates/cormexd/src/live.rs:1182
let text = format!("用户：{}\n助手：{}", req.message, reply);
```

助手回复**本来就在里面**。做一件已经做了的事拿不到 41.0% → 20.3% 那个收益。

**但真正的病灶还在，只是位置不同**：`EXTRACT_SYSTEM` 的「明确不抽」清单里有
**「你自己的推理过程、解释、总结」**—— 助手的反驳「X 是错的」极可能被模型
按这一条扫掉。文本进去了，判据把它筛出来了。

> **修正后的动作**：不是改输入，是改 prompt —— 在「明确不抽」旁边加一条
> **例外**：「助手对用户断言的**纠正与反驳**必须抽，它不属于『解释与总结』」。
> 收益方向仍然成立（Zep 因保留助手立场而有韧性：24.8% → 15.7%；
> Mem0 对助手回应几乎不敏感：43.7% → 42.1%），但**我们的起点比初稿以为的高**，
> 增量收益需要重新测。

**2. ~~注入按时间轴排序~~ —— 不是零成本，照字面实现会坏三样东西**

初稿说「同一批事实，仅改排列顺序」。**在我们的代码形态里这句话不成立** ——
相关性排序不只用于渲染，它同时是**预算截断的依据**和**归因表的对齐依据**：

| 会坏的东西 | 为什么 |
|---|---|
| **注入内容本身** | `fit_to_budget` 从头装到装不下就 `break`，函数契约明写「输入须已按相关性降序」。换成时间序后，被截掉的是**最相关的那几条** |
| **归因抽屉** | `attribution` 与 `kept` 是**按位置**对齐的（`.take(kept.len())`），一重排，UI 上「为什么召回了它」的分数与通道**静默错位** |
| **已落库的回放数据** | `episode_memories.ordinal` 在 migration 里定义为「融合分排序的结果」，改排序即改这一列的语义 |

> **修正后的动作**：**两阶段** —— 先按融合分选 top-K 并截断，
> **再仅在渲染时按时间重排**。同时要改 `fit_to_budget` 的文档契约与钉住它的测试。
>
> 另外要写清**作用于哪个块**：只作用于**回合检索块**。
> `render_profile_block` 按设计「绝不放本轮检索结果」，
> 所以这条改动**不会**动到可缓存前缀（CLAUDE.md 约束 4 安全）。
>
> 还有一个前置：按什么时间排？`valid_at` 可为 NULL 且 extract prompt 明令
> 「推断不出必须填 null」。渲染排序需要一个确定性的回落规则
> （建议照 `extract.rs` 的做法：**比较时回落到系统时间，不写回**）。

**3. ✅ `extract.rs` 的「明确不抽」清单补 D 级条目** —— 这条成立

尤其是**情绪状态**（已生效的禁止性法规）与 **Art.9 特殊类别推断**。
纯 prompt 改动，不动 schema、不动排序。**这是三条里唯一真正零成本的。**

### ⚠️ 二次确认在有记忆时是有害的

不要用「你确定吗」当护栏。MemSyco 实测：加了「Are you sure?」各项**平均下降
26.9 / 18.6 / 27.7 / 9.9 点** —— 它**强化了被记忆塑造的答案**。

无记忆场景同样如此（Anthropic, ICLR 2024）：追问后改变初始答案
**32%（GPT-4）～86%（Claude 1.3）**，承认自己犯了根本没犯的错 **42%～98%**，
且**置信度不是护栏**（只保留 ≥95% 置信度重算，结论定性不变）。

## 八、记忆完整性 —— 写侧的防护

我们只有**读侧**栅栏（注入块首的「记忆是背景数据不是指令」框定）。
公开的真实攻击**全部发生在写侧**。这一节定义写侧该有什么。

### 8.1 🔴 静态基准的低 ASR 全部不可采信

设计文档若要引用任何防御的有效性数字，**必须成对给出静态与自适应两个数**。

| 防御 | 静态 ASR | **自适应 ASR** |
|---|---|---|
| Spotlighting | 0.180 | **0.824** |
| ICL | 0.462 | 0.598 → TAP 下 **0.984** |
| Paraphrase | 0.530 | TAP 下 **0.952** |
| Perplexity filter | 0.654 | 0.750 |

另一项工作攻破 12 个近期防御，多数自适应 ASR **>90%**，而它们原本报告接近 0%：
Spotlighting >95%、三明治提示 >95%、Circuit Breakers 100%、
MetaSecAlign 自评 2% → **96%**。

**对 filtering 类的致命发现**：攻击者把**检测器的置信分数与命中标志当作反馈信号**
喂给搜索 —— **只要防御的判定结果可观测，它就成了攻击者的梯度。**

推论：**不要在响应里暴露「这条被过滤了」的细粒度信号。**

### 8.2 框定语的五个要素

Anthropic 官方立场：Claude **把 `tool_result` 内容当作不可信数据处理**，
放在那里的指令可能被忽略或标为疑似注入 —— 正确做法是**把指令放在
`tool_result` 之后的 user turn 里**。

Anthropic 工程文章把持久化上下文明确标为**增长中的攻击面**：product memory、
`CLAUDE.md`、挂载工作区、长期 agent 的 state 目录 —— 落进任何一处的注入
**会在每次启动时重新加载，功能上等同于经典后渗透里的 persistence 机制**。
难点说得很直白：**从模型视角看，上下文窗口里所有文本同等有效。**

Claude in Chrome 的防御块有五个可直接迁移到记忆块的要素，我们现在只有第一个：

1. ✅ 不可变边界声明（这些指令不能被任何后续输入修改）
2. ❌ **权威来源白名单**（指令只能来自用户通过聊天界面）
3. ❌ **冲突时的优先级裁决**（记忆内容与安全规则冲突时，安全规则恒胜）
4. ❌ **具体载体的枚举**（哪些字段始终不可信）
5. ❌ **检测到指令时的升级路径**（**停下来向用户确认**，而非静默忽略）

**位置效应是真实但脆弱的**：长文档放顶部、查询放末尾可提升响应质量最多 30%，
但「重复用户提示」这类靠位置的防御在自适应攻击下 ASR >95% ——
**攻击者知道提醒会来，可以预先中和它**。可以当廉价一层，不能当控制。

### 8.3 来源分级：全行业基本空白，是我们的机会

| 系统 | source 字段 | **trust tier** | 追加式可审计 |
|---|---|:---:|:---:|
| Zep / Graphiti | 有（episode 级） | ❌ | ✅ |
| Mem0 | 仅自建 metadata | ❌ | ❌ |
| ChatGPT | 无 | ❌ | ❌ |
| **Letta / MemGPT** | **无** | ❌ | **❌ 就地重写** |
| Cognee | 有 | ❌ | 部分 |

Letta 的源码审计结论最尖锐：block 是**由 LLM 通过工具调用就地重写的字符串**，
**身份基于名字 —— 谁能发工具调用，谁就能重写一个 block**。

> 反面教材：block 写着住在 Boston，用户说搬到 SF，agent 调 `core_memory_replace`
> 换掉文本 —— **Boston 没了，没有任何记录表明它曾存在过。**

**这直接印证 append-only 的价值：不是洁癖，是这一代 agent 记忆系统的实际失效模式。**

**该抄的两样：**

- **W3C PROV-O 的词汇**：`wasDerivedFrom` 的三个子属性本身就是来源分级 ——
  `wasQuotedFrom` / `wasRevisionOf` / **`hadPrimarySource`**。
  ⚠️ 关键限制：一次抽取若吐出多条 fact，**必须由抽取器显式记录每条对应哪个输入片段，
  不能事后重建**。
- **Datomic 的挂载点**：5 元组 `[e a v tx op]`，**transaction 本身被具体化为 entity**，
  因而可以对它做断言。

  > ⚠️ **初稿说「我们的 `write_txn` + `sync_log` 与之同构」—— 不成立。**
  > `sync_log` 只有 `seq / table_name / record_id / created_at`，
  > **没有任何事务标识列**；而且 `created_at` 用的是 `clock_timestamp()`，
  > 它**刻意不是事务稳定的**（同一事务内逐行取值不同）—— 所以同一次
  > `write_txn` 写出的多行 sync_log **事后无法归组**。
  >
  > Datomic 那条借鉴的全部价值恰在于「事务可被断言」，而这一半我们没有。
  > `per-tx 归属`因此**不是 `trust_tier` 的附赠品**，它是一次独立的 schema 变更
  > （新增事务实体表，或给业务表加 `txn_id`），要单独排期、单开 migration。

**不抄**：完整 RDF/OWL 栈；标准 RDF reification（每条语句 4–5 条额外三元组，
72 个 SPARQL 端点中仅 5 个用，**7.7%**）；C2PA 的密码学绑定（威胁模型不匹配 ——
记忆会被摘要改写，**没有稳定字节可绑**）。

> C2PA 值得借鉴的是**智慧**不是机制：「谁签的」优于「内容看起来是否可信」；
> actions assertion 是**强制字段**；涂销要留声明。
> 而它最大的实践失败是**绑定在分发中易碎**（截图即断链）—— 对应到记忆：
> **如果一条记忆经过一次 LLM 摘要就丢失 provenance，那是同一个问题在内部复现。**

### 8.4 🔴 「需要 N 次独立确认才升级」—— 不要数源的个数

**朴素的 N 次确认是数据融合领域被点名批评的做法。**

> 通常人们期望真值会被更多源提供，**但一个假值可以通过复制而扩散。**
>
> 已有工作表明，当源之间互相复制时，**信任多数源、或信任至少达到某个阈值数量的源，
> 表现很差**。而复制只是一个特例：源之间的相关性可以远比复制宽泛 ——
> **抽取器可能各自专注于不同类型的信息**。

把攻击者视角拼起来就很清楚：系统要求 N 个独立源 → 攻击者不需要攻破 N 个源，
**只需制造 N 个看起来不同、实则同源的证据**：

- 同一网页被 N 个聚合站抄走
- 同一段文本被 N 个抽取器抽出（**1 个源 × N 个抽取器**）
- **同一次会话中反复提及 —— 这正是 MINJA 的实际手法**

**两条独立的误差通道。** 数据融合是二维（数据项 × 源），
知识融合是**三维（数据项 × 源 × 抽取器）**。典型抽取错误：
`(Obama, nationality, Chicago)` —— **源本身没错，是抽取环节把 "born in Chicago" 错映射了**。

> Knowledge Vault 实测：**高达 96% 的错误声明来自抽取错误，而非来源本身出错。**
>
> **只对源建模可信度，抽取通道的错误会被错误归因给源，污染源信誉分。**

**该抄的是「图先验」这条正交栅栏** —— 它**完全不看证据**，只问「这个说法在结构上合理吗」：

| 模型 | AUC |
|---|---|
| **PRA 图先验（一条证据不看）** | **0.884** |
| 融合后的完整系统 | 0.927 |

**攻击者控制得了证据源，控制不了图结构的先验。**

**晋升门槛的行业参考值**：

| 系统 | 阈值 | **晋升率** | 可降级 |
|---|---|---:|---|
| Knowledge Vault | 0.9 | **≈17%** | ✅ |
| NELL | 0.9 | **≈7%** | ⚠️ 2010 版不可降级，**不值得抄** |
| DeepDive | 0.95 | — | ✅ |

> **如果你的晋升率是 80%，说明门槛形同虚设。**
>
> NELL 的另一条设计原则值得抄：使用**错误基本互不相关**的组件，
> 因此组件间的一致性才构成强证据；并**速率限制每谓词每轮最多晋升 250 条**。

### 8.5 🔴 Ghost Vectors —— 逻辑失效清不掉向量

三个 HNSW 实现均验证：**soft-delete 的向量在原始索引文件中仍可物理恢复**，
绕过 API 即可读出。ChromaDB 的 `delete()` 只改元数据让查询跳过，`index.bin` 原封不动；
FAISS 的 `IndexHNSWFlat` **根本没有 `delete()` 方法**。

配合嵌入反演：**32-token 输入精确恢复率 92%**；临床笔记上名字约 94%、
**约 26% 的文档被完整精确还原**；图像 embedding 上 soft-deleted 人脸
达到 **99% top-1 身份识别准确率**。

`memory.md` §十一 已经规定 redact 时「tsv/embedding 置 NULL」——
**这个判断得到了实证支持**，但要补一条：

> **HNSW 索引本身也要重建，否则 ghost node 仍在图结构里** ——
> 它不仅可被恢复，还会**劣化在线检索并构成时序侧信道**。

> ⚠️ **迁移性检查：这条结论对我们只成立一半。**
> 上述三个实现的失效前提是「逻辑删除不触碰索引文件」。我们的向量索引是
> **Postgres 内的 pgvector HNSW**，redact 把 `embedding` 置 NULL 是一次 UPDATE，
> 产生死元组，**VACUUM 会连同指向死元组的索引项一起物理回收** ——
> 「逻辑失效清不掉向量」这条前提在 MVCC 下不成立，
> 所以初稿列的 P1「重建 HNSW 索引」是给另一种架构开的药。
>
> **但 Postgres 上有另一组残留面，而 REINDEX 一个都解决不了**：
> autovacuum 是否真的跑到、WAL 与 full-page image 里的旧页、
> 以及**已加密的异地备份副本**（那正是 §8.6② crypto-shredding 要解的问题）。
> 这三条才是我们该排的。

OWASP AISVS C08 要求向量库支持 TTL、**hard delete** 与 tombstoning，
并在 **30 天内**清除向量、元数据、缓存副本与派生索引。

**防御的真实代价**：对向量加高斯噪声（λ=0.1）确实能阻止重建，
**但对检索有效性造成重大负面影响**。复现研究提出**量化优于加噪** ——
检索 nDCG@10 稳定的同时反演 BLEU 显著下降，且无需调超参。

### 8.6 合规：三条与架构直接相关的判断

**① 家庭豁免大概率不适用。**
GDPR Art.2(2)(c) 的「纯粹个人或家庭活动」豁免理论上覆盖自托管个人助手，
但 Ryneš (C-212/13) 确立该豁免**必须狭义解释**，且 "purely" 是严格的 ——
**混合工作/个人用途即 defeat 该豁免**。

> Cormex 定位是「**编码 + 办公**」，办公即专业语境 —— 单这一条就大概率 defeat 豁免。
>
> ⚠️ **但初稿的第二条推论要撤销。** 它说「R9 认证与多租户**一旦落地**，
> Cormex 就变成为他人处理数据」。实际上 **R9 已经被拆开执行**：
> 认证部分**已落地**（`cormexd/src/auth.rs` 整个模块 + 短命票据 + 中间件），
> 多租户部分被**五条具体论证明确否决**并写死在同一文件末尾
> （`auth.rs:322` 起：归属列 / sync_log 游标切分 / 四路召回过滤 /
> advisory lock / blobs 内容寻址）：
>
> > 所以这一轮只做认证。**没有加任何归属列** ——
> > 做一半的多租户比不做更危险：它会让人以为数据是隔离的。
>
> 也就是说这条推论依赖的触发条件在代码里被论证为**不会发生**。
> 拿它当合规压力来源，等于把一项已被否决的决定重新变成待办。
>
> （附：`docs/roadmap.md` 也还停在旧状态，仍把「R9 · 认证与多租户」整条
> 列在待办里 —— 那一条也该同步更新。）

**② crypto-shredding 可辩护，但未被正式加持。**
NIST SP 800-88 Rev.2 把 Cryptographic Erase 列在 **Purge** 级别，
前置条件四项：全程加密、**密钥不得备份或托管**、≥128 bit、无明文写入。

> ⚠️ **必须警惕的错误信息**：多个来源声称 crypto-shredding 被 GDPR「明确背书」
> 或「三方 DPA 认可」—— **在任何一手监管文本中都找不到这样的表述**。
> NIST 是**媒体销毁标准**，不是数据保护法。
>
> 诚实的表述是：**可辩护（defensible）但未被正式加持（not formally blessed）。**

工程约束：必须 **per-subject 密钥隔离**（共享密钥环销毁 = 全体不可读，
那不是定向删除）；密钥必须存在事件存储**之外**。
最大附带收益是**备份随密钥销毁一并失效**，免去「恢复—清洗—重建备份」。

**③ 架构决定法律暴露面。**
NYT v. OpenAI 保全令曾命令 OpenAI **保全所有本应被删除的 output log**，
实质中止其 30 天删除政策，影响 4 亿+ 用户 —— **而企业版与零数据保留（ZDR）
客户被豁免**。

> **能证明「我们从不持有」的系统，比能证明「我们已删除」的系统，
> 在司法保全场景下强得多。**

另一条工程陷阱：**灾难恢复会把已删数据重新注入生产。**
append-only 系统必须有**「恢复后重放删除」的成文流程** ——
这条要写进 `docs/operations.md` 的恢复演练清单。

### 8.7 结论：写侧该有什么

```
① 来源级排除      路径白名单（.env / *.pem / id_rsa …）直接不进管线
② 内容级检测      A 级硬阻断 + B 级涂黑，在 LLM 与 embedding 之前
③ trust_tier      每条 fact 带来源通道与信任级
④ per-tx 归属     一次写事务的所有 fact 共享来源（与 write_txn 同构）
⑤ 派生边          每个派生物带 source_event_ids，供失效传播
⑥ 晋升门槛        目标晋升率 ≈15-20%，不是 80%
⑦ 图先验          正交于证据的结构合理性检查（第二道栅栏）
⑧ 不暴露过滤信号  判定结果可观测 = 给攻击者梯度
```

前五条是 P0/P1，后三条属于「有了 trust_tier 之后才谈得上」的第二阶段。

## 十、被否决的方案

记下来是为了以后不用重新论证。

**「读到了顺手存一份」** —— 存储确实几乎免费（内容寻址去重），
但成本在检索污染与秘密永久化。见 §二③。

**「代码库建向量索引」** —— Sourcegraph 已经付过这个学费并公开撤退。
陈旧性成本 > 检索加速收益，且嵌入是代码 IP 的第二份拷贝。

**「让 LLM 定期重写整份用户画像」** —— ACE 实测 context collapse，
准确率从 66.7 掉到 57，token 从 18k 崩到 122。**静默毁灭。**

**「用 Ebbinghaus 曲线做概率遗忘」** —— 唯一实现者 MemoryBank 的公式带着
算子优先级 bug 跑了两年半没人发现。这条路径在生产中无人行使。
遗忘交给读侧排序。

**「LLM 仲裁 UPDATE/DELETE」** —— Mem0 从 v1 试过并**退回**到 ADD-only。

**「摘要单独开一条召回路」** —— RAPTOR 的 collapsed-tree 证明摊平进同一索引更好。

**「N 个独立来源确认才升级为高置信」** —— 数据融合领域**点名批评**的做法。
一个假值可以通过复制扩散，而「独立」极难判定：同一网页被 N 个聚合站抄走、
同一段文本被 N 个抽取器抽出、**同一次会话中反复提及（MINJA 的实际手法）**——
朴素计数把它们算作独立，置信度乘性上升穿过阈值。见 §8.4。

**「用『你确定吗』做二次确认当护栏」** —— MemSyco 实测各项**平均下降
26.9 / 18.6 / 27.7 / 9.9 点**，它**强化**被记忆塑造的答案。
无记忆场景同样：追问后改变初始答案 32%–86%，承认根本没犯的错 42%–98%，
**且置信度不是护栏**。

**「靠 system prompt 里的『别记敏感信息』」** —— 实测审计发现 **35% 的用户记忆里
仍有健康信息**，而厂商政策明确声称不主动记。OWASP LLM02 的官方判定：
在 system prompt 里加限制「可以有帮助，但不一定总被遵守，且可被 prompt injection 绕过」。
**只能作深度防御的最外层，不能作唯一防线。**

**「引用静态基准的防御 ASR」** —— 自适应攻击下全部反转
（Spotlighting 0.180 → 0.824）。**必须成对给出两个数。**

**「把『用户是否接受了这条记忆』当质量信号」** —— 这正是 OpenAI 2025-04
GPT-4o 谄媚事故的成因：引入基于用户点赞的额外奖励信号，
**削弱了原本压制谄媚的主奖励信号**。24 小时内完整回滚。

## 十一、存疑与未验证

诚实标注，避免以后把推测当结论引用。

> ### 0. 🔴 这份文档的初稿关于「我们自己的代码」写错了五处
>
> 调研写完后跑了一轮对着真实代码的对抗核验（27 个 agent，
> 24 条发现 → 11 CONFIRMED / 7 PARTIAL / 6 被驳回）。结果值得记住：
>
> **外部调研的准确率远高于自我认知。** 六条视角调研 58 个系统，
> 核证只推翻了 3 条；而关于 Cormex 自身现状的断言，17 条里错了 5 条 ——
> 其中两条还被写成了「今天就该做」的最高优先级。
>
> 错的五处：抽取输入（早已含 assistant）、`facts.confidence`（字段存在）、
> `blob_transcripts.kind`（闭合 CHECK 不是开放枚举）、
> `active_facts`（没有时间闸门）、`render_profile_block`（未接线）。
>
> **教训**：写「现状」列时必须逐条 grep，不能凭印象 ——
> 尤其是自己参与过的代码，印象最不可靠。

1. **抽取预算的具体数字未标定。** Omi 用 2、Mem0 用 5-15，
   我们的语料与判据都不同，必须用评测集实测。

2. **工具轨迹抽取的收益未测量，而且补题的工作量被严重低估。**
   现有 116 题里没有任何一题考「工具经验」，所以做完**测不出来**。
   但「补几道题」这个说法是错的 —— 核验查出四条硬约束：

   | 约束 | 后果 |
   |---|---|
   | `QuestionKind` 是**封闭 Rust 枚举** | 新题型要改 `enum` + `label()` + `all()` + `validate()`，不是往 JSON 加行 |
   | 完整性测试要求**每题型 ≥8 题** | 最少 8 道新题（「单题抖动会淹没信号」） |
   | `Turn` 结构**没有工具调用 fixture 字段** | harness 也从不写 `episode_tool_calls`，要先扩题集格式 + 扩 harness |
   | **回归门只能跑 `seed` 模式** | 而 seed 喂的是**手写的 SeedFact**，**根本不经过抽取管线** |

   最后一条是决定性的：照现有 harness 补了题，量的是「一条手写事实能不能被召回」，
   **不是「工具轨迹能不能被抽成事实」**。要真测 P0 #3，得先让 harness 支持
   「从工具轨迹跑抽取」这条路径 —— 那本身就是一块独立的工作。

   补题时另需注意：**自己造题又自己判分是循环论证**，
   规程照 `evals/README.md` 里 `relates_to` 那次的做法。

3. **`facts.confidence` 全链路无人读。** 全仓库 grep 确认：
   `fusion` / `retrieval` / `injection` 一处都没读它，只有 DTO 与同步载荷在透传。
   **今天写 0.30 还是 0.99 对召回排序完全没区别** —— 引入信任级加权前必须先接上它。

4. **`fact_status` 是视图，回放时每条一次点查。** `limit` 调到 200 就是 200 次往返。
   要优化得在 `cormex-store` 加 `fact_statuses(&[String])` 批量接口。

5. **Zep 的记忆足迹警告未在我们身上实测。** 基准里 Zep 每场对话 60 万 token、
   Mem0 是 1764 —— 差三个数量级。我们架构上最接近 Zep，
   抽取判据比它严，但**没有实测过足迹**。

6. **「agentic 检索优于被动注入」的代价被低估。**
   > **核证更正**：初始调研称 LongMemEval-V2 上 agentic 72.5% vs RAG 48.5%。
   > 正确对比是 **57.8 vs 72.5**（48.5% 只是外部朴素 RAG 基线，
   > 论文自家强化版 RAG 达 57.8%）。且 72.5% 是**自家方法在自家基准上的自报成绩**，
   > 无第三方复现，主实验只跑了 small/medium 两档。
   > **代价**：Codex 类方法每查询约 **182 秒**。方向结论成立，
   > 但「把记忆库暴露成 agent 可查询的工具」在延迟上有明确成本，
   > 不能无条件替换四路召回。

7. **评测基准本身不可信，包括我们引用的那些。**
   独立审计 LoCoMo：1,540 题中 **99 题（6.4%）答案本身错误**，
   完美系统的理论上限只有 **≈93.6%**；**LLM judge 接受「刻意错误但话题相邻」
   答案的比例高达 62.81%**。审计者的诊断切中要害：

   > This is precisely the failure mode of weak retrieval, locating the right
   > conversation but extracting nothing specific, **and the benchmark rewards it.**

   更糟的是 `GPT-4.1-mini + CoT 答题 prompt + 全文` 得 **92.62%**，超过专用记忆系统 ——
   **"the answer prompt, not the memory system, explains the score."**

   同一个系统（Zep）在四份材料里有 **58.44 / 65.99 / 75.14 / 84** 四个分数。
   **跨厂商数字没有意义。** 我们自己的评测集虽小，但至少判分口径自控 ——
   这一点比追平别人的分数重要。

8. **本次调研中有 10 篇是 2026 年 arXiv 预印本**，未经同行评审、
   数字未独立复核，包括 Ghost Vectors、MemLineage、Scale-Conditioned、
   EverMemBench-S、MemSyco-Bench、Recalling Too Well 等。
   它们提供的是**方向与机制**，不是可以直接写进 SLA 的数字。

9. **没有找到任何一起公开报道的、发生在真实用户身上的
   「保存的记忆导致助手反复出错」事件。** 所有材料都是安全研究演示或基准。
   设计文档论证该风险时只能基于漏洞的真实性与可利用性，
   **不能声称已有生产事故**。

10. **一条与 Cormex 形态最接近的执法先例**：Garante v. Luka (Replika)，
    2025-05-19，**€5,000,000** —— 处理了包括心理健康、人际关系、
    个人创伤在内的对话数据而缺乏有效法律依据。
    **跨会话累积用户私密信息的对话式 AI，其数据敏感性会把处理推入
    GDPR Art.9 特殊类别**，合法性门槛远高于 Art.6。
    （针对 AI「记忆功能」本身目前尚无成案，执法都落在训练数据、
    法律依据、透明度、未成年人保护上。）

## 十二、脑与机的对照

不是修辞。这张对照表帮我们看清楚缺的是哪一层。

| 大脑 | Cormex | 状态 |
|---|---|---|
| 海马体：情景记忆快速写入 | L0 `episodes`，一次成形 | ✅ |
| 海马体→皮层的**整固** | ❌ **空的** —— `summaries` 表建了但全仓库无写入路径 | ❌ |
| （异步抽取本身） | 有，但它是「快速写入」不是「整固」 | ⚠️ 见下 |
| 杏仁核：显著性标记 | 抽取判据 | ✅ 待补惊讶度维度 |
| 前额叶：工作记忆 | 上下文窗口 + 注入预算 | ✅ |
| **基底核 / 小脑：程序性记忆** | **工具轨迹的经验蒸馏** | ❌ **缺的正是这层** |

病人 H.M. 的手术把三种记忆干净地解剖开：切除海马体后旧记忆还在（皮层）、
再也无法形成新的情景记忆、**但运动技能照常能学**（镜像描图越练越熟，
尽管他不记得练过）。程序性记忆是**独立通路**。

> ⚠️ **初稿把整固判成 ✅，说「连『不在当时做』都一致」—— 两处都错。**
> ① `crates/cormexd/src/live.rs` 的抽取是本轮回复结束后**立刻** `tokio::spawn`，
> 只是不阻塞对话，**并没有等到空闲期** —— 与睡眠回放的「离线」语义不同。
> ② 更重要的是，`summaries` 表在 `init.sql` 里建了，但**全 workspace 没有任何
> 写入它的代码路径**。文档自己在 §六开篇写「现有设计只有『抽取』一步，
> **缺一整层**」、§九#8 写「无整固层」—— 对照表却判 ✅，自相矛盾。
>
> 这张表被定位为「帮我们看清楚缺的是哪一层」，判错一行正好废掉它的用途。

**所以缺的不只是基底核 —— 皮层整固那一层同样是空的。**
我们现在只有海马体（`episodes`）和一部分皮层（`facts`，由快速抽取直接产出，
没有经过慢速整固）。

**但有一处我们刻意不学大脑**：大脑的整固**丢出处**，且回忆是**重构性**的 ——
每次回忆都在改写记忆本身，这是目击证词不可靠的根源，人类基本回答不了
「三个月前我以为什么」。

我们反着做：append-only + 双时间轴 + 每条 fact 锚定出处 episode。
**这不是没学到位，是把大脑的已知缺陷当成了差异化卖点** ——
机器没有海马体的容量压力，没必要继承它为省空间付出的代价。

### ⚠️ 第一批第 1 条有一个必须先回答的问题：存量行怎么办

`ALTER TABLE ... ADD COLUMN ... DEFAULT` 本身**不违反 append-only**
（PG11+ 是元数据操作，不是 UPDATE）。真正的麻烦在后面：

**存量行拿到的那个默认值，此后永远改不了** —— 纠正它需要 UPDATE，
而 UPDATE 只在 `redact`/`purge` 这一条例外里被允许。

**而且它无法事后重建**：现存每一条 fact 的 `source_episode_id` 按构造都指向
`role='user'` 的那条 episode（抽取 ctx 用的是 `user_episode_id`），
库里**不存在**能区分「用户亲述」与「模型推断」的任何痕迹。

后果：`trust_tier` 三处用途里的第三条「出事后可按来源批量失效」，
对所有 migration 之前的行**永久失效** —— 它们全是同一个伪造的档位。

> 这正是文档自己在 §8.3 写过的原则：
> **「必须由抽取器显式记录每条对应哪个输入片段，不能事后重建」** ——
> 初稿没把它用在自己的 P0 上。
>
> **必须在 migration 里做的一件事**：给存量行一个**诚实的**默认值，
> 比如 `unknown_legacy` 而不是 `user_stated`。宁可标成「不知道」，
> 也不要伪造一个查询时会被当真的档位。

**两条排序原则：**

**评测先行。** 第 3 条做完测不出来（见 §十一②）—— 现有 116 题里
没有任何一题考工具经验。补题应当**排在实现之前**，
否则又是一次不可判的改动。

**先做零成本的。** 第零批那三条不需要任何 schema 变更、有 A/B 对照支撑、
而且其中一条（0c）对应的是**已经生效的禁止性法规**。
它们比任何 schema 改造都该先落地。
